RESTART-SAFE GASL V4 WORKFLOW EXAMPLES

These examples use only the planner-visible restart-safe command surface.
Every value consumed by a later action is a named durable StateStore variable.
Each consumer must also appear in that variable's persisted `usable_by` list.
PROCESS may select rows or expose fields that already have exact registered
bindings. It cannot create a new semantic fact.
Relation identities are exact typed scalars. Bare Boolean/numeric literals are
typed values. JSON-quote a string that looks Boolean/numeric, contains `,` or
`|`, case-insensitively equals the reserved GRAPHWALK wildcard `a`, `an`,
`any`, `all`, or `*`, or begins with the reserved `relation_type=` or
`relationship_name=` assignment prefix. Preserve exact case and punctuation.
GRAPHWALK requires unique actual tuples at its declared edge/depth grain and
fails instead of silently collapsing parallel or convergent occurrences.

Example 1: bounded exact enrichment

FIND nodes with entity_type=PERSON AS person_nodes
PROCESS person_nodes CONTRACT gasl_process_execution_v6 MODE exact_enrichment CARDINALITY exactly_input MAX_INPUT_ITEMS 72 MAX_MODEL_CALLS 8 REQUIRED_FIELDS [first_name] WITH materialize the exact registered first_name binding AS enriched_people
SHOW enriched_people limit 10

Example 2: deterministic graph projection

FIND nodes with entity_type=PERSON AS people
GRAPHWALK from people follow WORKS_AT depth 1 AS employment_paths
PROJECT employment_paths GRAIN edge FIELDS src_id,tgt_id,relation_type,path_depth KEYS src_id,tgt_id,relation_type,path_depth PRESERVE_MULTIPLICITY AS employment_rows
COLLAPSE employment_rows BY tgt_id COUNT AS employee_count AS employers
SHOW employers limit 10

Example 3: combine durable named results

FIND nodes with entity_type=PERSON AS people
PROJECT people GRAIN node FIELDS id KEYS id AS people_ids
PROJECT people GRAIN node FIELDS id KEYS id AS people_ids_copy
JOIN people_ids with people_ids_copy on id AS joined_people
SELECT joined_people FIELDS id AS selected_people
SHOW selected_people limit 10

Example 4: continue bounded PROCESS work

PROCESS enriched_people__unresolved CONTRACT gasl_process_execution_v6 MODE exact_enrichment CARDINALITY exactly_input MAX_INPUT_ITEMS 72 MAX_MODEL_CALLS 8 REQUIRED_FIELDS [first_name] WITH continue materializing the exact registered first_name binding AS enriched_people
SHOW enriched_people limit 10

PROCESS response shape, identity, provenance, required-field, call-budget, and
sidecar rules are supplied by the versioned execution contract. ITERATE,
UPDATE, RANK, AGGREGATE, COMPARE, COUNT, ON, SET, ADD_FIELD, and graph
mutation commands
are not part of this planner-visible surface.
Defined empty FIND and pure transform results are successful durable row sets;
later retained transforms preserve that defined emptiness. An `__unresolved`
sidecar is consumed only by its direct same-target PROCESS continuation.
An `__unsupported` sidecar is audit-only, may be read only by SHOW, and is
never a transform or PROCESS input. Both sidecar suffixes are runtime-reserved
and cannot be explicit output names.
