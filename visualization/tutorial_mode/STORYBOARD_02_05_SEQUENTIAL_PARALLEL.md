# Storyboard: 02–05 Locked Sequential Parallel Structure

This is the locked storyline for fragments `02` through `05`.

It does **not** use:

- a plot/map as the main device
- an eight-step explainer structure
- random system ordering

It **does** use the same story shape as fragment `01`, replayed with system
actors in sequence.

## The story shape we are repeating from 01

Fragment `01` established:

1. the popular image of knowledge is immediate insight
2. a bold claim can be attractive and still not be enough
3. modern science progresses by compiling information into evidence
4. the structure becomes legible only after collation and assembly

Fragments `02–05` must replay that same shape with system actors.

## The system actors, in order

The actors are not abstractions like “confidence” or “weakness.”
The actors are the systems themselves:

1. **Classic retrieval / database system**
2. **LLM-only**
3. **RAG**
4. **GASL**

Each actor faces the **same user question**.
Each actor should be shown in the same narrative slot:

- what it promises
- what it does well
- where it breaks
- why the next actor appears

That is the parallel structure.

## Fragment 02 — Classic system

### Purpose

Start with the first serious pre-GASL actor: the classic retrieval / database
system.

This is the “controlled, exact, but brittle” beat.

### What the audience should learn

- classic systems are precise
- they are efficient and structured
- but they struggle when the question and the data do not already fit the
  system’s expected form

### Visual story

- the same user question appears
- the classic actor responds through exact drawers, forms, keys, index cards
- it retrieves exact matches and rigid categories
- the result feels orderly
- then the mismatch appears: the question outruns the available slots

### Structural role

This is the first “strong but limited method” beat.

It maps to the part of the opening where a compelling move is made, but the
world is still too messy for that move alone to carry the argument.

## Fragment 03 — LLM-only

### Purpose

Now introduce the opposite actor: the system that can deal with uncontrolled
inputs and speak fluently across them.

This is the “immediate, articulate, attractive answer” beat.

### What the audience should learn

- the LLM can handle heterogeneous uncontrolled information
- in theory, it can ingest everything
- in practice, the cost/context burden is too high
- even when it answers well, the support structure is still not explicit

### Visual story

- the same user question appears again
- the LLM actor takes in the question easily
- it produces a smooth answer quickly
- the answer sounds better than the classic-system result
- then the weakness becomes visible:
  - the answer arrives before its support has been assembled
  - “can say” is not the same thing as “has compiled”

### Structural role

This is the direct analogue to the opening’s “bold claim” beat.

## Fragment 04 — RAG

### Purpose

RAG enters as the practical response to the LLM-only weakness.

This is the “targeted access” beat.

### What the audience should learn

- we cannot practically give the full world to the LLM
- so we retrieve a targeted slice
- that is a real improvement
- but retrieval can still be imprecise or incomplete

### Visual story

- the same user question appears again
- the system now uses targeted retrieval before answering
- we see a plausible slice being pulled from the larger information field
- the answer is more grounded than LLM-only
- but the weakness remains:
  - the slice may not be the right slice
  - the support is still only partially assembled

### Structural role

This is the “meaningful correction that still falls short” beat.

It should feel like progress, not caricature.

## Fragment 05 — GASL

### Purpose

GASL is the Tharp move in system form.

It is the first actor that changes the mode of work from
“retrieve and answer” to
“compile evidence and then answer.”

### What the audience should learn

- GASL does not win by sounding smarter
- GASL wins by forcing evidence into an explicit intermediate structure
- it makes retrieval, assembly, validation, and answer views visible

### Visual story

- the same user question appears again
- GASL does not rush to the answer
- it gathers, groups, checks, revises, and compiles
- answer views become visible before the final answer does
- the final answer appears only after the evidence has a legible structure

### Structural role

This is the exact parallel to Tharp in the opening.

Not more confidence.
Not a louder claim.
A more scientific mode of work.

## Continuity rules

Across 02–05:

- the user question stays constant
- each system actor gets the same narrative chance
- each fragment uses the same cue structure:
  - promise
  - action
  - limit
  - next actor

This is what makes the sequence feel like a story rather than a random
inventory of methods.

## What must not happen again

- no random switching between “design space” and “explainer mode”
- no turning the storyboard into the literal video
- no compressing all systems into one generic evidence workbench
- no producer-facing captions

The audience should feel:

1. why each system exists
2. why each system is not enough
3. why GASL changes the mode of work
